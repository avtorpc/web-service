# Место — web-service

Symfony 7.4 + Twig. Структура Kernel, config, src, public и bin основана на verification-service; его бизнес-логика, база и секреты не копируются.

Главная `/` и страницы `/*.html` отрисовываются Symfony через Twig. CSS/JS отдаёт Nginx. Регистрация соискателя и работодателя, подтверждение email и парольный вход подключены к микросервисам. Кабинеты, вакансии и резюме пока используют данные прототипа.

Из ONMI_infra: `make web-up`, затем http://localhost:8080. Остановка: `make web-down`.

Полный vendor хранится в Git; composer.lock фиксирует версии. При запуске web-service зависимости проверяются локально без обращения к Composer/Packagist. Локальный запуск использует общий gateway_nginx и запускает зависимости регистрации, включая базу и Kafka. Основной `make up` использует web-service вместо Next.js и существующий NGINX_PORT.

Для production задайте APP_SECRET, APP_ENV=prod, APP_DEBUG=0 и HTTPS. Текущая отдельная сборка предназначена для локальной разработки.

Полная локальная регистрация: из ONMI_infra выполнить `make registration-up`. Сайт — http://localhost:8080, письма — http://localhost:8025 (Mailpit). Тест цепочки: `python3 tests/registration-e2e.py` при работающем локальном стеке. Подробности: [registration-mvp.md](../../docs/flows/registration-mvp.md).

Состояние входа определяется серверной сессией web-service: cookie содержит идентификатор сессии, а токены auth-service остаются на сервере. Само подтверждение регистрации не означает вход. После парольного входа страница перезагружается; все страницы скрывают формы входа/регистрации и показывают email и форму выхода. POST /logout проверяет CSRF, уничтожает сессию и возвращает главную в гостевом режиме. При истечении access-токена интерфейс возвращается в гостевой режим; автоматическое продление сессии пока не реализовано.

## Кабинет работодателя

`/cabinet` показывает профиль, собственные вакансии и связанные блоки тестовых
заданий. `/cabinet/vacancies/new` открывает форму из пяти разделов по прототипу;
`/cabinet/vacancies/{uuid}/edit` восстанавливает сохранённый черновик.
Для сохранения черновика обязательно только название. Данные хранятся
в catalog-service; браузер передаёт изменения через web-service с проверкой
сессии и CSRF. Повторное сохранение обновляет существующую запись, а изменение
в другой вкладке вызывает сообщение о конфликте.

Поиск работает по названию и городу на текущей странице (20 вакансий).
Кнопка «Получить тестовое задание» пока показывает сообщение-заглушку:
обращений к ИИ и создания фиктивных заданий нет. Публикация доступна кнопкой «Опубликовать» в списке вакансий.
«Снять с публикации» возвращает запись в черновик для редактирования. Скрипт кабинета — `public/js/employer-cabinet.js`;
прежний скрипт HTML-прототипа сохраняется отдельно.

Главная страница и `/vacancy.html?id={uuid}` загружают опубликованные вакансии
из публичного API catalog-service через web-service. Источники вакансий из
HTML-прототипа и localStorage больше не используются. По умолчанию показаны
все опубликованные вакансии, независимо от даты. Пустая база и недоступный
сервис имеют разные сообщения; при ошибке демонстрационные записи не
подставляются. Фильтры и поиск применяются к данным каталога. Вкладка работников
пока сохраняет демонстрационные резюме. Реальные отклики пока не подключены;
кнопки отклика отключены, чтобы не сохранять фиктивные отклики в браузере.

Проверка опубликованной тестовой записи без входа и без изменений данных:
`python3 tests/public-vacancy-live.py --id <uuid>`.

## Отклики и чаты

`/cabinet/chats` — переписка соискателя и работодателя. `/cabinet/chat-api/*` проверяет серверную сессию и CSRF для изменений. Основные токены auth-service остаются на сервере; браузер получает только короткий токен node-chat для Socket.IO. HTTP сохраняет сообщения, Socket.IO уведомляет участников; после разрыва соединения история дочитывается по seq.

Отклик создаётся на странице опубликованной вакансии: название/текст резюме и сопроводительное сообщение. Резюме и снимок сохраняются в catalog-service; диалог и сообщения — в node-service. Повторный отклик открывает существующую запись без замены снимка. В кабинет работодателя добавлены ссылки по каждой вакансии. Решения и оценка относятся к отклику; генерация задания работодателя остаётся заглушкой.

Быстрый отклик с главной: POST /applications/start-chat через web /cabinet/chat-api/apply-chat. Первый клик сохраняет снимок профиля (kind=profile, resume_id=NULL) и создаёт общий диалог; повторный возвращает тот же отклик и чат, не заменяя ранее отправленное резюме. Готовое резюме для начала переписки не требуется.

## Сессия авторизации

Вход сохраняется при бездействии и закрытии браузера. Короткий access-токен автоматически обновляется через `/auth/refresh`; refresh-токен без срока истечения хранится только в серверной сессии web-service, в auth-service — его SHA-256. Браузер получает только HttpOnly cookie с длительным сроком хранения. Очистка cookie или серверного хранилища сессий потребует повторного входа; браузер может ограничивать срок хранения cookie.

Кнопка «Выход» с CSRF-проверкой отзывает текущий refresh-токен через auth-service и уничтожает серверную сессию. Другие входы этого аккаунта сохраняются. Токены доступа и чата остаются короткими; временная недоступность auth-service возвращает ошибку без удаления сессии.

Миграция `Version20261009210000` применяется обычной командой `make registration-up` из ONMI_infra. Проверка на временных аккаунтах: `make auth-session-test` (Python 3 на машине, тесты автоматически очищают свои данные).

## Поставка vendor в Git

В репозитории web-service хранится полная папка `vendor`, включая автозагрузчик, метаданные Composer и лицензии библиотек. Контейнер запускает `php bin/check-vendor.php` и PHP-FPM без сетевой установки зависимостей. Если vendor отсутствует или версии/коммиты пакетов не соответствуют composer.lock, запуск завершается с понятной ошибкой вместо попытки скачать пакеты.

Обновление выполняется на машине с доступом к репозиториям: `composer install --no-interaction --prefer-dist`, затем `php bin/check-vendor.php`. Сохраняйте изменения composer.json, composer.lock и всего vendor вместе. Для осознанного изменения версий используйте composer update; при развёртывании обновлять версии не нужно.

Это относится только к web-service. Остальные PHP-сервисы по-прежнему выполняют composer install в `make registration-deps`; Git, Packagist и загрузка базовых Docker-образов для всего стека этой доработкой не отключаются. Локальные .env, var, журналы и секреты остаются исключены из Git.
